The development loop

Every change is a story, and pnpm verify is the gate

1

/pickup-story

Loads the minimum vault notes and states the acceptance criteria.

2

/new-branch

Branches from an up-to-date main.

3

Build + test

Unit, Testcontainers, Playwright, flutter test.

4

pnpm verify

Lint, policy doc check, coverage floor, integration.

5

/ship-story

Status flip, commit with Story: trailer, PR.

Business values (fares, windows, radii, timeouts) live only in apps/api/src/config/policy/policy.schema.ts; docs/POLICY.md is generated from it. HITL stops (secrets, ADRs, real deploys, demo sign-offs) always go to the owner.

docs/onboarding/workflows/ · story-lifecycle.md · testing.md · business-config-changes.md

A PreToolUse hook blocks commits that touch code without a Story trailer. Migrations are hand-authored SQL and are not applied on restart; rehearse them on a copy first, as database-migrations.md explains. The full HITL list is in 95-delivery/hitl-touchpoints.md.
