# Web (passenger app) videos (W01-W10)

Generated by `apps/web/e2e/demo/record.mjs` (see [apps/web/e2e/demo/README.md](../../../../apps/web/e2e/demo/README.md)); do not edit
by hand, re-run `pnpm demo:record:web`. All recordings are of the **dev** stack, headless Chromium 1280x720 (W07: two 640x720 panels
side by side), with an in-page caption bar naming the scene, the current step and the state-machine chips reached so far.

How to read them: the passenger web app is real (it runs from this checkout). The driver in each scene is a **scripted simulator**
(`lib/driver-sim.ts`) speaking the real driver protocol (Socket.IO `driver:location` / `ride_offer` / `ride_offer_response`, REST
`POST /v1/rides/:id/state`, `/cancel`), standing in for the Flutter driver app; the real driver UI is in the driver videos
(`../driver/INDEX.md`). Sessions are minted by the harness for fixture users (never by the shipped app/API; see the README).

Related reading: [docs/onboarding/state-machines.md](../../state-machines.md), [docs/POLICY.md](../../../POLICY.md) (dispatch, scheduled,
rides knobs), [docs/ARCHITECTURE.md](../../../ARCHITECTURE.md), [ops videos](../ops/INDEX.md), [driver videos](../driver/INDEX.md).

## What recording these found

Fixed while preparing the scenes (each with a regression test):

- **No "Later" booking in the web app** (W08): the API supported `scheduled` rides but the page had no time picker. Added a Now / Later
  picker (`apps/web/src/app/book/schedule-picker.tsx`, `lib/booking/schedule.ts`, window mirrored from `booking.schedule*Ms` in
  `docs/POLICY.md`), a "Scheduled for ..." tracking banner until the T-10 min wake, and `scheduledFor` on the ride create / detail
  responses (`apps/api/src/modules/rides/rides.controller.ts`) so a reload restores it.
- **Raw enum shown to riders in a shared booking** (W07): the pool line read `Pool: 3d6df489... · seat 2 · closed_full`; it is now
  "Shared ride · 2 seats taken · Pool is full, finding your driver" (`lib/booking/pool-status.ts`, `data-testid="pool-status"`).
- **A `no_show` ride was not treated as terminal when restoring or clearing the active ride** (W05), commit `fd8b2ca`.

Open product gaps seen on camera (not fixed; too large for this pass):

- **Shared rides have no live tracking in the web UI** (W07): after booking a share the rider sees a text status line only; there is no
  driver position, no per-stop progress and no cancel (the API has no member leave in Phase-0, see state-machines.md section 3). The
  booking form (including the Book button) also stays on screen under the pool status.
- **Opener of a pool pays the solo fare** (W07): rider 1 saw an indicative per-seat price of 73.30 but "Your fare: 104.72 (fixed when
  you joined)", the stand-in `fixed_at_join` policy (RCAB-E8.S9 revisits it).
- **A 2-rider pool never reports `closed_full`** with the shipped `matching.maxSeats = 3`; it closes by the 60 s timeout. Worth knowing
  when you read the "pool open -> closed_full" wording in older notes.
